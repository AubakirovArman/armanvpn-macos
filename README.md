# armanVPN

Other platform: [ArmanVPN iOS](https://github.com/AubakirovArman/armanvpn-ios).

Нативный macOS-клиент для шлюзов Check Point. SwiftUI-интерфейс управляет отдельным VPN-ядром на основе [snx-rs](https://github.com/ancwrd1/snx-rs). Check Point Endpoint Security для работы не нужен.

## Friends Edition

Внутренняя фановая версия: постер Армана с логотипами из предоставленной иллюстрации, собственная иконка приложения и окно в строке меню. Фактический объём RAM определяет реакцию Армана: скепсис на 8 ГБ, ирония на 16 ГБ, одобрение на 32 ГБ и отдельная реплика для больших конфигураций. Юмор не влияет на доступность подключения. При подключении появляется «Ты в мощной сети Армана».

Оригинальный постер: `armanVPN/Assets.xcassets/ArmanPoster.imageset`. Три прозрачных аватара находятся в `ArmanSkeptical`, `ArmanUnimpressed` и `ArmanApproved.imageset`. Они и иконка созданы встроенным `image_gen`; точные промпты сохранены в `design/imagegen-prompts.json`, исходник иконки — в `design/arman-app-icon-source.png`.

«Управление → Скопировать данные для отзыва» копирует версию, macOS, RAM и состояние теста, без логина, пароля и адреса шлюза.

## DMG для доверенных тестеров

```sh
bash scripts/build-universal-engine.sh
bash scripts/build-dmg.sh
```

Получится `dist/armanVPN-Friends-1.3-universal.dmg` и файл SHA-256. Внутри — Release-приложение для Apple Silicon и Intel, ссылка на Applications и «Начать здесь.txt». Пароли, пользовательские профили и решения о доверии к сертификатам из текущего Mac в образ не включаются. Для сборки оформление DMG записывается через dmgbuild, без автоматизации Finder.

Сборка подписывается имеющимся сертификатом разработчика. При Apple Development она остаётся внутренней тестовой сборкой без нотариализации Apple: на другом Mac может потребоваться личное разрешение первого запуска в «Конфиденциальность и безопасность». Инструкция находится внутри DMG; глобальное отключение Gatekeeper не требуется. Для обычного распространения без этого шага нужны Developer ID и notarization.

Поведение интерфейса визуально проверяется через DEBUG-команду `--render-previews <папка>`: она рендерит собственные SwiftUI-представления с демонстрационными данными и отключённым сетевым монитором. В Release-сборку экспортёр не входит.

## Возможности

- Сервер, порт, логин и пароль; способы входа загружаются со шлюза.
- Пароль сохраняется только в macOS Keychain, если включена соответствующая галочка. В исходниках, UserDefaults и конфигурационных файлах пароля нет.
- При первом подключении приложение показывает сертификат, срок действия и SHA-256. Есть отдельная галочка «Запомнить доверие к этому сертификату». Без неё решение действует в текущем сеансе приложения; с ней — после перезапуска. Новый сертификат всегда требует нового решения.
- Доверие ограничено точным сертификатом и адресом шлюза. Системное хранилище доверенных сертификатов не меняется. Проверка сертификатов в VPN-ядре включена.
- SSL по умолчанию, также доступен IPsec через UDP/TCP; маршруты и DNS устанавливаются по параметрам шлюза.
- Фоновая служба через SMAppService, меню в строке macOS, журнал без паролей и MFA, восстановление после разрыва.
- Десятиминутный тест непрерывности сессии: переподключение считается провалом, а не продолжением теста.

## Обновление 1.3

При первом запуске обновления сохранённый профиль IPsec однократно переводится
на SSL / AutoDetect. Адрес сервера, учётная запись, ссылка на пароль в Keychain
и решения о доверии к сертификатам сохраняются. Позднейший ручной выбор протокола
не переопределяется. Активный туннель приложение автоматически не перезапускает:
после замены предыдущей версии нужно один раз отключиться и подключиться снова.

В исследованном подключении IPsec шлюз выдавал Office Mode адрес на 120 секунд.
Ядро начинало продление через 60 секунд, не получало ответ за 10 секунд и завершало
туннель. Переход на SSL обходит этот механизм IKEv2; причина отсутствия ответа
на продление IPsec пока не установлена. После ручного переподключения SSL прошёл
600-секундный тест с 30 успешными HTTPS-проверками внутреннего GitLab и без смены
сессии. Проверялось открытие страницы входа; содержимое проекта не запрашивалось.

В текущей версии реализован вход по логину/паролю и дополнительному коду MFA. Браузерный SSO и клиентские сертификаты пока не реализованы в интерфейсе.

## Сборка

Требуются macOS 14+, Xcode и Rust 1.94.0. Ядро собирается для архитектуры текущего компьютера.

```sh
rustup toolchain install 1.94.0 --profile minimal
bash scripts/build-engine.sh
bash scripts/build-app.sh
```

Готовое приложение: `.build/xcode/Build/Products/Debug/armanVPN.app`. Настройте собственную команду подписи в Xcode для сборки на другом Mac. Сертификат Apple Development подходит для локальной разработки. Публичный дистрибутив требует Developer ID, Release-сборки и notarization.

Первое включение:

1. Поместите приложение в `/Applications` и запустите его.
2. Выберите «Управление → Разрешить службу…» в блоке системной службы.
3. Разрешите её в «Системные настройки → Основные → Объекты входа и расширения». macOS может показывать имя владельца сертификата разработчика.
4. Введите сервер, порт и логин, проверьте сервер и примите сертификат, если доверяете ему.
5. Введите пароль и подключитесь. Если нужно, включите сохранение пароля.

Приложение работает вне App Sandbox: отдельная фоновая служба создаёт `utun`, маршруты и DNS через API macOS. Это реализация с LaunchDaemon; VPN-профиль Network Extension в системных настройках она не создаёт. Работа туннеля продолжается после закрытия окна и завершения интерфейса. Отключить его можно из окна или меню приложения.

## Проверка

```sh
swift test
cargo +1.94.0 test --manifest-path .build/snx-rs/Cargo.toml --locked -p snxcore --features vendored-openssl
bash scripts/build-probe.sh
```

`tools/ConnectionProbe.swift` выполняет реальный тест: 600 секунд проверяет неизменность VPN-сессии и, если задан `healthHost`, TCP-доступность внутреннего сервиса на порту 443. Учётные данные получает через JSON в stdin, не через аргументы командной строки. Запускайте только после явного одобрения SHA-256 сертификата. После успешного теста туннель остаётся подключённым.

Пример схемы входа, без настоящих учётных данных:

```json
{"host":"vpn.example.com","port":"443","username":"user","password":"...","fingerprint":"ОДОБРЕННЫЙ SHA-256","loginType":"vpn","tunnel":"SSL","seconds":"600","healthHost":"10.0.0.1","save":"false"}
```

`action: "inspect"` только проверяет сертификат и получает способы входа. `save: "true"` сохраняет пароль в Связку ключей и профиль в UserDefaults. Без переданного пароля тест может использовать пароль, ранее сохранённый в Связке ключей. Личные результаты тестов находятся в игнорируемой папке `.local`.

Исходники и лицензия изменённого ядра описаны в [engine/UPSTREAM.txt](engine/UPSTREAM.txt); патч и AGPL включаются в приложение.

## Диагностика разрывов

Версия 1.2 показывает фактический тип туннеля, состояние сетевого интерфейса и
последнюю причину отключения. Ядро хранит в памяти до 128 событий с фиксированными
кодами: IKE DELETE, истечение сессии, тайм-аут keepalive, ошибки управляющего
обмена и продления Office Mode. Пароли, ключи сессий и содержимое пакетов в эти
события не записываются. При перезапуске ядра история очищается.

Кнопка «Начать тест» включает наблюдение за существующей VPN-сессией.
Проверка доступа к внутреннему сервису выполняется отдельно тестовым инструментом.

## Public source and local settings

No VPN server address, VPN account, password, accepted server certificate, private key or signing team is supplied.
Each user configures their own gateway and credentials in the app. The numeric addresses in protocol tests are example fixtures, not a configured VPN connection.
Select your own Apple signing team in Xcode before building a signed app. Local build files, logs and user settings are excluded from Git.
